# Contributing to AYINLA

1. Create a branch from `main` named `feature/short-description` or `fix/short-description`.
2. Keep changes focused and document business assumptions.
3. Run `npm run lint`, `npm run check`, `npm run build` and `npm run test:routes` before proposing a merge.
4. Include before/after mobile and desktop screenshots for layout modifications.
5. Do not introduce em dashes or en dashes into authored copy.
6. Do not publish unapproved client garments, testimonials, personal data or secrets.
7. Open a PR and wait for CI to pass. Do not merge failing changes.
8. Record roadmap changes in `docs/ROADMAP.md`, rather than creating a parallel plan.

## Content editing

Initial content currently lives in `src/lib/site.mjs`. Once Pages CMS is implemented, use the structured content files and reviewed editorial workflow.
